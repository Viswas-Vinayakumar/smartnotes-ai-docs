Technical documentation · v1

SmartNotes-AI

A macOS app that records university lectures, transcribes them on-device, and turns each one into structured notes that merge into a single living notebook per course.

Version 0.1.0 (v1) · October 2026 · Swift 6 · macOS 15+ · Apple Silicon · by Viswas Vinayakumar

1Overview

Lectures are long, dense and spoken. Students record them, but recordings are rarely re-listened to, and the useful parts — what the professor stressed, which homework is due when, what a term means — get lost. SmartNotes closes that gap: press Record at the start of a lecture and Stop at the end. A few minutes later the course's notes page has a new session with a summary, topic-by-topic notes, the professor's remarks, any deadlines (already in your calendar), new glossary terms, open questions and course organisation — every item linked to the second of audio where it was said.

On-device speech

Audio is transcribed by Whisper on the Mac's Neural Engine. Recordings never leave the machine.

Structured, not a wall of text

Claude fills a strict JSON schema; the app — not the model — decides how a lecture merges into the course.

One notebook per course

Lecture 7 adds to lectures 1–6: deadlines are re-dated instead of duplicated, glossary definitions are refined, admin changes keep their history.

Resumable by design

Five steps, each writing a file. A crash, a usage limit or a network failure resumes from the last finished step.

Acts on what it hears

Confident deadlines go to your calendar; vague ones ("sometime in November") are flagged for you to confirm.

Shareable, safely

One click publishes a read-only copy for classmates — no transcripts, no audio, no code, behind an unguessable link.

2Use cases

Each use case lists the trigger, what the system does, and the guarantee it gives.

UC-1 · Record a live lecture

Actor: student, laptop open in the lecture hall. Trigger: Record.

  1. The app asks for microphone access once, creates a session folder named after the date (2026-10-05, or 2026-10-05-2 for a second lecture that day) and starts capturing.
  2. The toolbar shows a breathing red dot, the timer and live level bars; a red line breathes across the notes; a record icon appears in the menu bar; idle sleep is disabled.
  3. On Stop the last audio chunk is finalised and the pipeline starts.

Guarantee: at most the current five-minute chunk can be lost, even if the app is force-killed.

UC-2 · Back-to-back lectures

A lecture ends; while it is being processed the next one begins. Fifteen minutes after Stop, if nothing is recording, the app sends one notification — "Next lecture starting? Tap Record to capture it." — whose Record button starts recording in the same course. Processing and recording run side by side.

UC-3 · The lecture ended but the recording didn't

After 60 seconds of digital silence the app warns that the microphone may be muted. After five minutes below speech level it asks "It's been quiet for 5 minutes — is the lecture over?" with Stop recording / Keep recording, as a notification and as an in-app banner.

UC-4 · A German lecture

Whisper detects the language per chunk; Claude is instructed to write all notes in English, translating faithfully and keeping the original technical term in parentheses where it matters. The transcript stays in the original language.

UC-5 · A missed lecture, recorded by a friend

Drag a Voice Memo, mp3 or mp4 onto the window. It becomes a session dated with the file's creation date and is processed exactly like a recording. An older lecture imported later never overrides dates or admin values stated in newer lectures.

UC-6 · Deadlines without a planner

"Homework one is due on the ninth of October at noon" becomes a deadline on 9 Oct 12:00 and a calendar event "Course: Homework one". If the professor later says it moved, the same event moves and the page records "Moved from …". If the date was vague, the row shows ⚠ check this and nothing is synced until you pick a date and confirm.

UC-7 · Revising for the exam

Click any timestamp to hear the professor say it. Highlight the lines that matter (select → Highlight or ⌘⇧H); they collect in a Highlights section and survive every later lecture. The professor's "Exam hint:" asides sit under their topic. Export the page as HTML or one long PDF.

UC-8 · Sharing with classmates

Publish pushes a read-only page of the course to a separate public GitHub repository served by GitHub Pages, under a random twelve-character path. The link is copied to the clipboard. Classmates refresh to see new lectures.

UC-9 · Something went wrong

Claude usage limit reached, Claude not logged in, calendar access revoked, laptop crashed mid-recording: the failed step's dot turns red with a plain-language reason (hover for it) and Update retries from that step. A crash during recording is detected at the next launch and the interrupted session is processed automatically.

3Architecture

SmartNotes is a single Swift package with three targets: a UI-free core library that holds every rule, a thin SwiftUI app shell, and a test executable. External systems are reached only through narrow protocols, so each can be faked in tests.

Design principles

  • The model extracts, the code decides. Claude only describes one lecture. Identity, de-duplication, history and user state are deterministic Swift (NotebookMerger), so results are testable and never silently rewritten.
  • Every step leaves a file. Transcription takes minutes and Claude can hit limits; a failure must never mean starting over.
  • User state is sacred. Ticks, confirmed dates and highlights are never reset by a merge.
  • Protocols at the edges. Transcriber, NotesEngine, CalendarWriter and ProcessRunner are protocols; tests inject fakes, and a future local model is a new conformance.
  • One renderer, three outputs. In-app page, export and published page come from the same code with a published flag.
  • Plain files. Anyone can open the data folder and understand it.

4The pipeline

Pipeline.process(_:) runs a stopped session's unfinished steps in order. Before a step runs, its status is saved as running (the UI's pulsing blue dot); afterwards done, or failed(reason) — and the run stops. processAllPending() walks every course, oldest session first, and retries failed steps. The app calls it after Stop, after an import, at launch and when you press Update; a request that arrives while a run is in progress sets a flag that makes the loop go round once more instead of starting a second run.

The merge is idempotent: merging a session that is already in the notebook returns it unchanged, so re-running step 3 after a crash between "merged" and "marked done" is harmless.

5Recording

Audio graph

Recorder.start optionally points the engine's input unit at the microphone chosen in Settings (Core Audio kAudioOutputUnitProperty_CurrentDevice, resolved from the device UID), creates the session's audio/ folder, installs a tap on the input node and starts AVAudioEngine. It also begins a ProcessInfo activity with .idleSystemSleepDisabled, so the Mac does not idle-sleep in a quiet lecture.

Per buffer, handle(_:) converts to mono, writes it, advances seconds (time excludes pauses), computes the RMS level of the first channel in dBFS and feeds both detectors with the recorded-time clock. A write failure is reported through onError and shown as a banner.

Device changes and sleep

When the input changes (headset plugged, AirPods connect, wake from sleep) the engine posts AVAudioEngineConfigurationChange and stops itself. restartAfterConfigurationChange() closes the current chunk, re-reads the new input format, rebuilds converter and writer continuing the chunk numbering, reinstalls the tap and restarts — then onRestart sends a "Microphone changed" notification. Recording never silently ends.

Pause, stop, quit

Pause pauses the engine (no buffers, so no time and no audio). Stop removes the observer and tap, stops the engine, closes the writer, ends the power activity and marks the session stopped using the on-disk copy so step statuses written meanwhile are kept. Quitting with ⌘Q calls the same stop through the app delegate, so the open chunk is finalised.

Chunked writer

ChunkedAudioWriter writes part-NNN.m4a files of chunkSeconds (300 s). Each closed chunk is a complete, playable AAC file — a crash loses at most the chunk in progress. The bit rate is 64 kbps at microphone rates (≥ 32 kHz) and 24 kbps at low rates, which AAC requires. At launch, quarantineUnreadableAudio renames any chunk AVFoundation cannot open (typically half-written at a crash) to .corrupt, so transcription skips it instead of failing.

// Rotation: open a new file when none is open or the current one is full.
if file == nil || framesInChunk >= AVAudioFramePosition(chunkSeconds * format.sampleRate) {
    try rotate()            // close, chunkCount += 1, open part-%03d.m4a
}
try file!.write(from: buffer)

Silence and quiet detection

SilenceDetector is a tiny state machine: the first level below the threshold starts a stretch; when the stretch reaches limit seconds it fires once; any level at or above the threshold resets it.

public mutating func feed(levelDB: Float, at time: Double) -> Bool {
    guard levelDB < thresholdDB else { silentSince = nil; fired = false; return false }
    let start = silentSince ?? time
    silentSince = start
    if !fired && time - start >= limit { fired = true; return true }
    return false
}

Two instances run side by side. The mic check (−50 dB, 60 s) catches a muted or covered microphone. The long-quiet detector (SilenceDetector.longQuiet(): −45 dB, 300 s) is looser because a lecture hall is never digitally silent — ventilation and rustling sit around −50 to −45 dB, speech well above. Live transcription is not available during recording (it runs after Stop), so "no proper speech" is judged from level alone; the threshold is meant to be tuned on real lectures.

Recording nudges

  • Quiet prompt. Recorder.onLongQuiet → AppModel sets quietPrompt (a yellow banner with Keep recording / Stop recording) and posts a notification in category quiet with actions stop and keep.
  • Forgot to record. stopRecording() captures the course before stopping, then schedules a UNTimeIntervalNotificationTrigger of 900 s with the fixed id forgot-record, category forgot (action record, which brings the app forward) and the course slug in userInfo. Starting a recording or quitting removes the pending and delivered request.
  • Routing. A NotificationHandler (the notification-centre delegate) returns [.banner, .sound] so notifications appear even while SmartNotes is in front, and forwards action ids to AppModel.handleNotificationAction.
  • Battery. Every second while recording, if on battery at ≤ 15 %, one "Plug in" notification per recording.

Importing files

Importer.importFile opens the file as an AVURLAsset, requires an audio track, creates an imported (already stopped) session dated with the file's creation date, and exports the audio with AVAssetExportPresetAppleM4A to part-001.m4a. On failure the half-created session folder is removed, so no empty lecture is left behind. Video files work because only the audio track is exported.

6Transcription

WhisperKitTranscriber is an actor: the first call downloads the model (~1 GB) into models/ under the data folder, prewarms and loads it; later calls reuse the loaded instance. Each chunk is transcribed with language detection on and special tokens skipped. Chunk timestamps start at zero, so Transcript.stitch shifts every chunk by the total duration of the chunks before it.

Cleaning the transcript

  • Bracketed inline markers such as [BLANK_AUDIO] are removed; whitespace is collapsed.
  • Segments that are entirely a marker — […] or (Music) — are dropped.
  • Known silence hallucinations are dropped: text containing amara.org, Untertitel im Auftrag, Untertitelung, Copyright WDR…, or consisting only of Vielen Dank / Danke. Whisper learned these from subtitled video and produces them on silence.
  • The transcript's language is the one with the most kept segments across chunks.
  • An empty result fails the step with "No speech detected in the recording" rather than sending nothing to Claude.

The prompt form is one line per segment: [m:ss] text (or [h:mm:ss] past an hour), produced by formatTimestamp.

7Notes engine (Claude)

ClaudeCodeEngine conforms to NotesEngine. It shells out to the Claude Code CLI using the student's own login, so there is no API key in the app and nothing to bill separately.

Invocation

claude -p "<instructions>" \
  --output-format json \
  --json-schema '<LectureExtract.jsonSchema>' \
  --tools "" \
  --no-session-persistence
# stdin:
LECTURE DATE: 2026-10-05
COURSE CONTEXT (JSON): {"glossaryTerms":[…],"openDeadlines":[…],"topics":[…]}
TRANSCRIPT:
[0:04] Good morning, today we continue with …
  • No tools: the model can only answer, not read files or run commands.
  • No session persistence: lectures don't pile up in Claude Code's history.
  • Environment: ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN are removed (they would override the subscription login and bill the API), as are CLAUDECODE and CLAUDE_CODE_* (a nested session would confuse the child). Homebrew paths are prepended to PATH.
  • Process runner: stdin, stdout and stderr go through temporary files, not pipes, so a two-hour transcript cannot deadlock on a full pipe buffer.

The prompt

The instructions (in NotesEngine.swift) ask for: English notes even for non-English lectures; exactly five summary bullets; topics in order with concise bullets that keep definitions, formulas, examples and numbers; professor's notes classified as emphasis, exam_hint, opinion, favorite or testing_style and attached to a topic title; every dated task with relative dates resolved against the lecture date, the exact words said and a confidence; glossary terms reusing existing spellings; open questions; and admin items. It ends with "Never invent content that is not in the transcript."

The course context — topic titles so far, glossary terms and open deadlines with their ids — lets Claude recognise "the homework I mentioned last week" and return its existing_id. It is told never to carry a date over from the context: a date is given only if this lecture states one.

Validation and retry

parseReply finds the first { in stdout (the CLI can print warnings first), reads the result envelope and prefers structured_output (already validated by the CLI against the schema), falling back to the result text. classify maps stderr/stdout text to usageLimit ("usage limit", "rate limit", "limit reached"), notLoggedIn ("not logged in", "/login", "invalid api key", "authentication") or failed with the first 300 characters.

Dates are validated strictly — the string must round-trip through a non-lenient formatter, so 2026-02-30 is rejected. t is seconds from lecture start, taken from the [m:ss] stamps.

Change in v1 (5 Oct 2026)Generated "exam prep" questions were removed from the schema, prompt, model and page. The professor's own exam hints remain as asides under their topics. Notebooks saved before the change still load: Swift's decoder ignores the old key.

8The course notebook

Data model

A Deadline carries both its current due/time (possibly edited by you) and statedDue/statedTime/statedOn — the date last said in a lecture, and which lecture said it. It syncs to the calendar when shouldSync: it has a date and is either high-confidence or confirmed by you. Otherwise needsConfirmation shows the ⚠ flag.

All notebook writes go through Store.updateNotebook: load → modify → save under one process-wide lock, so a pipeline merge and a tick in the page can never overwrite each other.

Merge rules

NotebookMerger.merge(notebook, extract:, sessionId:, date:) is a pure function. If the session is already present it returns the notebook unchanged.

  • Sessions are appended and kept in date order (2026-10-02 < 2026-10-02-2 < 2026-10-03).
  • Topics are appended with this session's id; each professor's note is attached to the topic whose title matches (case- and punctuation-insensitive), otherwise kept as a loose note of that session.
  • Glossary: a new term is added; a known term with a different definition gets a refinement; a repeated definition is ignored.
  • Open questions are appended with ids <session>-qN.
  • Admin: the latest value wins and the previous one moves to history ("Was: … (until lecture of …)") — but only if this session is not older than the one that set it.

Deadlines

If the lecture is newer, the deadline's said quote is updated to the latest wording either way.

9Notes page (renderer)

Renderer(today:, published:) turns a notebook (plus transcripts) into one self-contained HTML document with inline CSS and scripts — no network requests, so it works offline, as an export, and on GitHub Pages. All user and transcript text passes through escapeHTML (& < > " '), so a transcript containing <script> is shown as text.

Page structure

  • Upcoming: open deadlines due today or later, soonest first, at most three.
  • Notes: for each session in order, its topics numbered across the course, each with a session tag and timestamp, followed by an aside of the professor's notes; then that session's loose notes.
  • Deadlines: sorted by due date (undated last). In the app, open deadlines get a date control: flagged ones show "⚠ check this" + Confirm; confident ones hide it behind "edit" → Change date.
  • Folded sections (fold(_:_:count:_:)): Glossary, Open questions (count = unresolved), Course info and Transcripts render as <details class="fold"> with the heading as the summary. A section renders open if it contains one of your highlights.
  • Fold script (app and published page): a click on a contents link or highlight jump opens the folded section it points into; a click on a section header adds a class that animates the opening (a 0.35 s fade), so reloads restore open sections without animating.
  • Published mode: no transcripts, no highlights, no app links; tick boxes become static symbols; timestamps become plain text; a noindex, nofollow robots meta tag is added.

Highlighter

Every highlightable piece of text is wrapped in <span data-hl="BLOCK">, where the block id is stable across re-renders:

Block idText
sum:<session>:<i>summary bullet
t:<ti>, t:<ti>:b<j>, t:<ti>:p<k>topic title, bullet, professor's note
lp:<i>loose professor's note
d:<id>:title, d:<id>:saiddeadline title and quote
g:<key>:def, g:<key>:r<j>glossary definition and refinement
q:<id>, a:<key>open question, course-info value

A highlight stores (block, quote, occurrence) — the n-th non-overlapping match of the quote inside that block. The page script computes the same occurrence from the selection offset, so one selection spanning several items becomes several highlights. The renderer wraps matches in <mark id="hl-…">, skips overlaps, and lists every highlight (found ones link to their mark). Selection inside collapsed content or across existing marks is ignored.

10Calendar sync

CalendarSync.sync walks the notebook's deadlines. For each one that shouldSync, it builds an event — title "Course: Deadline", the date (all-day) or the time (one hour), notes with the exact quote and a marker line smartnotes:<deadline id> — and a signature title|date|time. If the deadline already has an event id and the same signature, it is skipped; otherwise the writer upserts and the new id and signature are stored. Events are never deleted, not even when a deadline is ticked done.

  • Finding the event again: EventKitCalendarWriter.upsert first tries the stored id; if the id changed (Google/CalDAV resyncs can do that) it searches ± one year in the chosen calendar for an event whose notes contain the marker line; only then does it create a new event.
  • No duplicates under concurrency: SyncGate allows one sync per course. A sync requested while one runs sets a "go again" flag instead of starting a second, duplicate-creating sync.
  • Partial failure: sync works on a snapshot; ids written before a failure are copied back into the latest notebook under the lock, so a retry doesn't recreate them.
  • Google Calendar works when the Google account is added in System Settings › Internet Accounts — it then appears in the calendar picker.

11Publishing

The Publish button shares a course as a read-only website. It never touches the app's own repository.

  • Secret path: 12 random characters from a–z0–9 (≈ 62 bits), generated once and stored in user defaults. The site root is blank and robots.txt disallows crawling.
  • No history: a brand-new build folder (never a reused .git) plus a force push means old content is not kept in the public repo.
  • Identity: commits use GitHub's no-reply address, so the public repo never shows the user's email.
  • Timeouts: every gh/git call is killed after 120 s, so "Publishing…" can never hang forever.
  • What is public: notes as rendered in published mode. Not transcripts, not audio, not highlights, not code. The repository itself is public, so the notes are readable by anyone who finds it — a deliberate choice, recorded on 2 Oct 2026.

Crash recovery at launch

13The Mac app

Structure

  • SmartNotesMain: a WindowGroup (min 900 × 600), a Settings scene and a MenuBarExtra (inserted only while recording, with Pause/Resume and Stop). The app delegate stops a running recording on quit.
  • AppModel (@MainActor ObservableObject): all state — courses, selection (remembered), sessions, recording state, level, elapsed time, processing/publishing flags, status text, banner, quiet prompt, reload token. View state lives here because @State's macro plugin is unavailable in a Command-Line-Tools build.
  • launch() runs once per app run: notification delegate and categories, permission request, crash recovery, re-render of all courses, restore the last course, then update().
  • refresh() recomputes the status pill ("Transcribing · Course · 1/5"), reloads courses and sessions and bumps the reload token.

Window

  • Sidebar: courses (+ to add) and the selected course's lectures, newest first, each with five step dots — grey pending, pulsing blue running, green done, red failed (hover for the reason) — and a caption with the running step or the failure.
  • Toolbar: Record — or, while recording, the breathing dot, "Recording"/"Paused", timer, level bars, Pause/Resume, Stop — then Import, Export (HTML / PDF), Publish, the status pill and Update.
  • Notes: NotesWebView (a WKWebView with read access to the course folder). On reload of the same page it saves the scroll position and the ids of open folded sections as JSON, reloads, and restores both when loading finishes. Drag files onto it to import.
  • Activity lines along the top of the notes: a breathing red 2 px line while recording (grey and still when paused), a 2 px progress line while processing or publishing.
  • Banners slide in from the top: messages with Dismiss, and the quiet prompt with Keep / Stop.

15Design system

The rules live in DESIGN.md and apply to every screen, page, icon and export — including this document.

Feel

Quiet, paper-like, typographic — a well-set book, not a dashboard. Content first; chrome recedes.

Colour

Ink #1a1a1a on paper #ffffff/#f7f5f0; dark #e8e8e8 on #161616. Colour only for state: blue working, green done, red failed / recording, amber needs attention, a soft marker.

Type

Notes in Georgia 17/1.75; UI and headings in the system sans; section labels in small caps (0.7 rem, 0.16 em tracking).

Layout

One 740 px reading column, 1 px rules, no cards or boxes except the Upcoming strip.

Motion

Calm and slow (0.3–0.4 s ease-in-out; breathing 1.6 s), never blinking or bouncing. Activity is noticeable, not demanding.

Words

Short, plain, friendly; say what happened and what to do next.

Development process

17Security and privacy

  • Audio never leaves the Mac. Recording, storage and transcription are local.
  • Transcript text goes to Claude through the user's own Claude Code login, with tools disabled and no session persistence. No API key is stored or used; environment keys are stripped so they cannot redirect billing.
  • Escaping: all lecture-derived text is HTML-escaped before rendering; the page cannot be made to run injected script.
  • Publishing sends only published-mode HTML to a separate public repository; transcripts, audio, highlights and code are excluded. The link path is random, the root is blank and crawlers are disallowed — but the repository is public by design, so published notes should be treated as public.
  • Identity: published commits use the GitHub no-reply address.
  • Permissions: microphone and full calendar access are requested with plain-language reasons; the app is ad-hoc code-signed so macOS remembers the grants.
  • Consent: record lectures only where recording is permitted, and consider professors' rights before sharing notes widely.

19Roadmap

  1. Ask my course (RAG). Chunk transcripts and notes, embed them locally, retrieve for a question and answer with citations that are timestamp links. Evaluated on a hand-written question set.
  2. On-device model (fine-tuning). Distil Claude's transcript→notes behaviour into a small open model with MLX LoRA on Apple Silicon; compare it with Claude on the same evaluation set; offer it as an offline engine — a new NotesEngine conformance.
  3. Provider choice. Anthropic API key, local Ollama and others.
  4. iPhone recorder reusing SmartNotesCore and WhisperKit.
  5. Sharing upgrades. Encrypted published pages (key in the URL fragment); unpublish and roll back.
